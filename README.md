# 🛡️ پنل مدیریت پروکسی MTProto تلگرام

پنل ساده و حرفه‌ای برای ساخت و مدیریت پروکسی‌های MTProto با سه حالت اتصال،
بهینه‌سازی خودکار شبکه (BBR) و پشتیبانی از کانال اسپانسر.

- **بک‌اند:** FastAPI (Python) — **دیتابیس:** SQLite — **موتور پروکسی:** mtprotoproxy
- **اجرا:** سرویس systemd روی Ubuntu — **UI:** فارسی، مینیمال، با Tailwind

---

## ⚡ نصب (روش گیت — پیشنهادی، برای آپدیت آسان)

روی سرور اوبونتو:

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/sina99778/mtproto-panel /opt/mtproto-panel
cd /opt/mtproto-panel && sudo bash install.sh
```

نصب‌کننده به‌صورت خودکار: پیش‌نیازها را نصب می‌کند، BBR و sysctl را فعال می‌کند،
موتور پروکسی و دیتابیس ASN را دانلود می‌کند، سرویس را راه می‌اندازد و در پایان
**آدرس پنل، نام کاربری و رمز عبور** را چاپ می‌کند.

> پس از نصب: `http://IP-سرور:8088` — کاربر `admin` — رمز در خروجی نصب.
> **حتماً بعد از اولین ورود، در «تنظیمات» رمز را عوض کنید.**

## 🔄 آپدیت

چون با git نصب شده، آپدیت فقط یک دستور است (داده‌ها و تنظیمات کاملاً حفظ می‌شوند):

```bash
sudo bash /opt/mtproto-panel/manage.sh update
```

این دستور آخرین نسخه را `pull` می‌کند، وابستگی‌ها را به‌روز می‌کند، **مهاجرت دیتابیس** را
خودکار اجرا می‌کند و سرویس را ری‌استارت می‌کند. دستورات دیگر مدیریتی:

```bash
sudo bash /opt/mtproto-panel/manage.sh status     # وضعیت پنل و پروکسی‌ها
sudo bash /opt/mtproto-panel/manage.sh logs       # لاگ زنده
sudo bash /opt/mtproto-panel/manage.sh backup     # بکاپ data/ در /root
sudo bash /opt/mtproto-panel/manage.sh uninstall  # حذف سرویس‌ها (داده باقی می‌ماند)
```

## 🧭 راهنمای کاربر نهایی (۴ قدم)

1. **ورود:** آدرس پنل را باز کنید و با نام کاربری/رمز وارد شوید.
2. **ساخت پروکسی:** روی «پروکسی جدید» بزنید، یک نام و پورت انتخاب کنید، نوع اتصال را
   انتخاب و «ساخت و اجرا» را بزنید. Secret خودکار ساخته می‌شود.
3. **اشتراک‌گذاری:** در داشبورد روی «کپی لینک» بزنید (یا «QR» برای اسکن). همان لینک
   `https://t.me/proxy?...` را به کاربران بدهید — با یک کلیک در تلگرام وصل می‌شوند.
4. **کانال اسپانسر (اختیاری):** هنگام ساخت پروکسی، تگ گرفته‌شده از ربات
   [@MTProxybot](https://t.me/MTProxybot) را در فیلد «تگ اسپانسر» بگذارید تا کانال شما
   بالای لیست چت کاربران تبلیغ شود.

## 🔌 سه حالت اتصال

| حالت | کاربرد | فیلدهای لازم |
|------|--------|--------------|
| **مستقیم (FakeTLS)** | ساده‌ترین حالت؛ ترافیک شبیه TLS واقعی و عبور از DPI. | پورت، دامنه FakeTLS |
| **تانل‌شده** | این سرور (ایران) فقط رله‌ی کم‌تأخیر است و به پروکسی شما در خارج فوروارد می‌کند. | آدرس + پورت سرور خارج (Secret و دامنه باید با خارج یکی باشد) |
| **کلودفلر** | مخفی‌کردن IP مبدا پشت Cloudflare. | دامنه edge، پورت edge + توکن/Zone در تنظیمات |

### ⚠️ نکته‌ی صادقانه درباره‌ی کلودفلر
کلودفلر **رایگان** فقط HTTP/WebSocket را پراکسی می‌کند، اما MTProto یک پروتکل
**TCP خام** است که کلاینت رسمی تلگرام مستقیم صحبت می‌کند. بنابراین مخفی‌کردن IP پشت
کلودفلر برای MTProto فقط با **Cloudflare Spectrum** (پلن پولی، پراکسی TCP) ممکن است.
این پنل از طریق Spectrum API این کار را خودکار می‌کند (و هنگام حذف پروکسی، اپلیکیشن
Spectrum را هم پاک می‌کند تا منبعی هدر نرود). اگر Spectrum ندارید، از حالت
**تانل‌شده** با یک IP تمیز خارجی استفاده کنید که همان هدف (مخفی‌کردن سرور اصلی) را
برآورده می‌کند.

> برای مخفی‌سازی کامل در حالت کلودفلر، پورت origin روی سرور همچنان عمومی است؛ برای
> سفت‌وسخت‌کردن، در فایروال فقط رنج‌های IP کلودفلر را به آن پورت اجازه دهید.

## 📊 آمار و مانیتورینگ

صفحهٔ **«آمار»** در پنل (به‌روزرسانی خودکار هر ۱۰ ثانیه) این موارد را نشان می‌دهد:

- **کاربران متصل (آنلاین)** — تعداد اتصال‌های فعال هر پروکسی (از `ss`).
- **کل ترافیک عبوری / مصرف** — مجموع بایت‌های جابه‌جا‌شده + سرعت لحظه‌ای هر پروکسی.
- **تعداد استفاده‌ها (سشن) و کاربران یکتا**.
- **اپراتور کاربران** — تشخیص اپراتور/ISP از روی IP کاربر (دیتابیس آفلاین ASN).

یک نمونه‌بردار سبک در پس‌زمینه هر ۱۵ ثانیه (`PANEL_STATS_INTERVAL`) داده‌ها را از سیستم‌عامل
می‌خواند؛ پس برای هر سه حالت اتصال کار می‌کند و وابسته به موتور پروکسی نیست.

> ⚠️ **محدودیت اپراتور در توپولوژی Paqet:** اگر پنل روی سرور خارج باشد و کاربران از طریق تونل
> Paqet برسند، IP واقعی کاربر روی سرور خارج `127.0.0.1` دیده می‌شود؛ پس آمار **اپراتور** فقط
> در حالت **مستقیم** یا **رله‌ی داخلی پنل** دقیق است (بقیهٔ آمار در همهٔ حالت‌ها کار می‌کند).
> دیتابیس ASN را نصب‌کننده به‌صورت best-effort از DB-IP دانلود می‌کند؛ اگر دانلود نشد،
> اپراتور «نامشخص» می‌ماند و باقی آمار سالم است.

## 🌉 تونل مقاوم با Paqet (KCP/UDP) — ضد قطع‌شدن

برای اینکه پروکسی «به این راحتی قطع نشود»، بهترین توپولوژی این است: **پروکسی واقعی روی
سرور خارج** اجرا شود و کاربران به **سرور ایران** وصل شوند؛ مسیر ایران↔خارج با تونل
[Paqet](https://github.com/behzadea12/Paqet-Tunnel-Manager) (KCP روی UDP، با محافظت
در برابر RST injection و اتصال‌مجدد خودکار) حمل شود.

```
کاربر تلگرام ──TCP 8443──▶ سرور ایران ──[Paqet KCP/UDP 443]──▶ سرور خارج ──localhost:8443──▶ mtprotoproxy ──▶ تلگرام
                          (Front در لینک)                      (پنل + پروکسی)
```

**مراحل خلاصه:**
1. **خارج:** پنل را نصب کن و یک پروکسی **Direct (FakeTLS)** روی پورت `8443` بساز. (Secret/دامنه را نگه دار.)
2. **خارج:** Paqet را نصب کن، نقش **Kharej/سرور** (گزینهٔ ۲)، listen port مثلاً `443/UDP`، secret key تولید و ذخیره کن.
   ```bash
   bash <(curl -fsSL https://raw.githubusercontent.com/behzadea12/Paqet-Tunnel-Manager/main/paqet-manager.sh)
   ```
3. **ایران:** همان نصب‌کننده، نقش **Iran/کلاینت** (گزینهٔ ۳)، IP و پورت خارج + همان secret key، و **forward port = `8443` (TCP)**.
4. **پنل (خارج):** در همان پروکسی، فیلد **«آدرس نمایشی / Front»** را برابر **IP سرور ایران** بگذار. حالا لینک داشبورد، IP ایران را نشان می‌دهد — همان را به کاربران بده.

**فایروال:** خارج → `ufw allow 443/udp`؛ ایران → `ufw allow 8443/tcp`. برای مخفی‌سازی کامل
IP خارج، پورت `8443/tcp` را روی سرور خارج از اینترنت ببند (تونل از localhost به آن می‌رسد).

**نکات مهندسی:** سرور ایران حتماً **KVM** باشد (raw socket/libpcap نیاز است، روی OpenVZ کار نمی‌کند). اگر UDP در ایران throttle شد، پورت/مود KCP (`fast/fast2/fast3`) را عوض کن یا MTU را به `1200` کاهش بده؛ در نهایت می‌توان به یک تونل TCP (مثل حالت تانل داخلی پنل یا backhaul/rathole) سوییچ کرد.

## 🛠️ مدیریت سرویس

```bash
systemctl status mtproto-panel      # وضعیت پنل
systemctl restart mtproto-panel     # ری‌استارت پنل
journalctl -u mtproto-panel -f      # لاگ زنده‌ی پنل

systemctl status mtproxy-<id>       # وضعیت یک پروکسی مستقیم/کلودفلر
systemctl status mtrelay-<id>       # وضعیت یک رله‌ی تانل
```

- مسیر نصب: `/opt/mtproto-panel`
- دیتابیس و بکاپ: `/opt/mtproto-panel/data/panel.db` (برای انتقال، فقط همین فایل + `panel.env` را کپی کنید)
- تنظیمات شبکه: `/etc/sysctl.d/99-mtproto-panel.conf`

## 🔒 ملاحظات امنیتی

- پنل با دسترسی **root** اجرا می‌شود (برای مدیریت سرویس‌های systemd و فایروال). آن را
  روی یک سرور اختصاصی نگه دارید.
- پورت پنل (`8088`) را پشت یک IP محدود یا تونل SSH قرار دهید و حتماً رمز قوی بگذارید؛
  در صورت امکان جلوی آن یک reverse proxy با TLS بگذارید.
- `data/panel.env` شامل کلید نشست و رمز اولیه است؛ دسترسی آن `600` است — تغییرش ندهید.

## 📁 ساختار پروژه

```
mtproto-panel/
├── install.sh                     # نصب‌کننده/آپدیتر هوشمند (BBR/sysctl/systemd/git)
├── manage.sh                      # مدیریت: update / status / logs / backup / uninstall
├── VERSION                        # نسخهٔ پنل
├── requirements.txt
├── README.md
├── sysctl/
│   └── 99-mtproto-panel.conf      # تنظیمات BBR و TCP
├── systemd/
│   └── mtproto-panel.service      # یونیت سرویس پنل (قالب)
└── app/
    ├── main.py                    # روت‌های FastAPI (auth/dashboard/CRUD/settings)
    ├── config.py                  # پیکربندی از روی متغیرهای محیطی
    ├── database.py                # لایه‌ی SQLite
    ├── auth.py                    # هش رمز (PBKDF2)
    ├── utils.py                   # تولید Secret، ساخت لینک FakeTLS، اعتبارسنجی
    ├── engine.py                  # تولید config.py برای موتور mtprotoproxy
    ├── proxy_manager.py           # ساخت/اجرا/توقف/حذف اینستنس‌ها با systemd
    ├── relay.py                   # رله‌ی TCP کم‌تأخیر (حالت تانل)
    ├── cloudflare.py              # کلاینت Cloudflare Spectrum API
    ├── nettune.py                 # خواندن وضعیت BBR
    ├── stats.py                   # جمع‌آوری آمار (ss + دلتای بایت + سشن)
    ├── geoip.py                   # تشخیص اپراتور از روی ASN (آفلاین)
    ├── templates/                 # base / login / dashboard / proxy_new / settings / stats
    └── static/                    # app.js (کپی/QR) + style.css
└── tests/
    ├── test_app.py                # تست یکپارچه‌ی کل اپ (۳۴ بررسی، systemctl ماک‌شده)
    ├── test_stats.py              # تست آمار (parser ss، دلتای بایت، اپراتور)
    └── test_relay.py              # تست عملکردی رله‌ی TCP
```
